# 产品与技术方向池（待决策）

> 文档定位：**调研与建议池，供决策使用，不代表已排期**。
> 流程：从本文挑方向 → 你拍板 → 采纳的先更新 [ARCHITECTURE.md](ARCHITECTURE.md)（架构影响），再更新 [ROADMAP.md](ROADMAP.md)（排期），最后把本文状态改为「已采纳」。
> 工作量估算口径：1 人、含联调，不含服务端开发（除非注明）。

当前基线：单麦 INMP441 + MAX98357A、半双工、MP3 播放、自建云端、无配网/OTA/屏幕/AEC。

---

## 1. 硬件方向（H）

| 编号 | 方向 | 说明（背景 + 方案） | 工作量 | 风险 | 状态 |
|---|---|---|---|---|---|
| H1 | **加第二颗 INMP441（双麦）** | 两颗麦共用 BCLK/WS、L/R 引脚一高一低；配软件参考通道即可上 AFE `"MMR"`，一次拿到**语音打断 + 双麦增强（降噪/波束）**。是当前硬件下性价比最高的一步 | 硬件 0.5d + 固件 2~3d（含延迟标定） | 麦克风间距/结构影响效果；需实测标定 | 待决策 |
| H2 | **换专业 codec（ES7210+ES8311 / ES8388）** | 带 ADC 回采通路，标准 AEC 方案；音质、稳定性最好；支持模拟输入复用（外接音源） | 改板 + 驱动 3~5d | 改板成本、PCB 重画 | 待决策 |
| H3 | **加屏幕（SPI/QSPI LCD + LVGL）** | 显示状态/歌词/封面/配网引导；需要额外 1~2MB PSRAM 做帧缓冲、内部 RAM 做驱动 | 硬件 + 5~8d | 内存与刷新率、UI 工作量 | 待决策 |
| H4 | **电池 + 充电 + 电量计** | 便携形态必需；含充电管理、电量 ADC、低电提示、休眠策略 | 硬件 + 3~4d | 功放峰值电流与电池放电能力匹配 | 待决策 |
| H5 | **SD 卡槽** | 本地音乐/日志/离线资源；缓解 16MB Flash 压力 | 硬件 + 1~2d | 卡座成本、文件系统稳定性 | 待决策 |
| H6 | **按键/旋钮/触摸扩展** | 现只有 1 个按键；旋钮调音量、多按键做播放控制体验更好 | 硬件 + 1~2d | 结构与成本 | 待决策 |
| H7 | **麦克风结构与腔体优化** | 开孔位置/尺寸、减震、喇叭与麦克风隔离、防啸叫；直接影响唤醒率和音质 | 结构迭代 2~3 轮 | 需打样验证，周期长 | 待决策 |
| H8 | **电源与 EMI 优化** | 功放独立 5V、独立 LDO 供麦、去耦与地平面、喇叭线屏蔽；解决底噪和掉压重启 | 1~2d 调试 | 需示波器/频谱实测 | 待决策 |
| H9 | **主控升级评估（ESP32-P4 等）** | 若后续要"屏幕 + 双麦 + 音乐 + 视频"并发，S3 的算力/内存会吃紧；P4 有更强算力与更多外设 | 重估 2~3 周 | 生态/驱动成熟度、成本 | 待决策 |
| H10 | **外壳与散热** | MAX98357A 满功率会发热；外壳需考虑散热孔、喇叭腔体密封、麦克风导音 | 结构件 | 开模成本 | 待决策 |

## 2. 功能方向（F）

| 编号 | 方向 | 说明（背景 + 方案） | 工作量 | 风险 | 状态 |
|---|---|---|---|---|---|
| F1 | **配网（BLE / SoftAP + 手机）** | 现在 WiFi 账号写死在固件里，换环境必须重烧；量产必备 | 3~5d | BLE 配网与音频并发内存 | 待决策 |
| F2 | **OTA（app + model + assets）** | 分区已预留 `ota_0/ota_1/otadata`，代码未实现；含回滚、版本上报、灰度 | 3~5d | 变砖风险，需回滚验证 | 待决策 |
| F3 | **定制唤醒词** | 现用"嗨，乐鑫"；定制需乐鑫 WakeNet 训练（2~4 周），固件侧只换模型 | 训练 2~4 周 + 固件 1d | 训练效果、费用 | 待决策 |
| F4 | **离线命令词（MultiNet）** | 断网也能"下一首/音量加/暂停"；model 分区有 1.5MB 余量 | 2~3d | 命令词误触发，需调阈值 | 待决策 |
| F5 | **语音打断（AEC）** | 当前半双工，播放完才能说话；配合 H1/H2 实现"随时打断" | 依赖 H1/H2 + 3~5d | 回声消除效果、双讲性能 | 待决策 |
| F6 | **音乐格式扩展（AAC/FLAC/HLS）** | 现在只支持 MP3；曲库若给 AAC/HLS 则必须扩展 | AAC 2d / FLAC 2d / HLS 3d | 解码内存与 CPU、HLS 分片逻辑 | 待决策 |
| F7 | **音乐源接入（曲库直链 / 第三方）** | 端侧播放器已支持 URL/文件，缺服务端曲库协议对接 | 1~2d（端侧） | 版权/URL 有效期 | 待决策 |
| F8 | **本地音乐（SD/FATFS 曲库）** | 无网也能放歌；配 H5 使用 | 2~3d | 索引/扫描性能 | 待决策 |
| F9 | **多语言** | 唤醒词、ASR、TTS 都要配套；海外市场前提 | 3~5d | 各语言唤醒词资源 | 待决策 |
| F10 | **声纹识别/个性化** | 区分家庭成员、个性化推荐/权限；主要靠云端 | 3~5d（端侧采集配合） | 隐私合规 | 待决策 |
| F11 | **音量自适应 / 夜间模式** | 按环境噪声自动调音量；夜间限幅；成本低体验提升明显 | 1d | 需噪声估计 | 待决策 |
| F12 | **断网本地降级** | 断网时仍可唤醒+提示音+播放本地内容，而不是完全不可用 | 2d | 状态机复杂度 | 待决策 |
| F13 | **播放队列/收藏/断点续播** | 音乐场景体验项，需服务端配合 | 2~3d | 与服务端联动 | 待决策 |
| F14 | **蓝牙音箱模式（A2DP Sink）** | 手机直连当音箱用；S3 支持 BT | 3~5d | 与 WiFi 共存资源竞争 | 待决策 |
| F15 | **本地技能（定时器/提醒/记事）** | 不依赖大模型的确定性强需求，体验好 | 2~4d | 时间同步、提示音资源 | 待决策 |
| F16 | **多音色/情感 TTS** | 主要为服务端能力，端侧仅参数透传 | 1~2d（端侧） | 依赖云端音色库 | 待决策 |

## 3. 质量与体验方向（Q）

| 编号 | 方向 | 说明（背景 + 方案） | 工作量 | 风险 | 状态 |
|---|---|---|---|---|---|
| Q1 | **唤醒率/误唤醒实测与调优** | 用 `record_wav.py` 采集不同距离/噪声/角度样本，形成基线数据；调阈值与增益 | 1~2d | 需要多场景采集 | 待决策 |
| Q2 | **首字时延优化** | 链路打点（唤醒→上行→ASR→TTS→出声），找出瓶颈逐段优化 | 1~2d | 受云端影响，需协同后端 | 待决策 |

| Q4 | **长稳与内存看护** | 24h/72h 压测、堆水位告警、任务栈水位、看门狗策略 | 1~2d | — | 待决策 |
| Q5 | **交互反馈体系** | 统一提示音、LED 颜色/呼吸/闪烁语义、错误音区分 | 1~2d | 设计资源 | 待决策 |
| Q6 | **语音交互体验打磨** | 打断后恢复、误唤醒后回退、连续对话免唤醒（follow-up）、静音超时提示 | 2~3d | 状态机复杂度 | 待决策 |

| F2 | OTA | ★★★★★ | 中 | 无（分区已留） | 量产前必做 |

| F4 | 离线命令词 | ★★★★ | 低 | 无 | 一期后可选 |
| F11 | 音量自适应/夜间模式 | ★★★☆ | 低 | 无 | 随时可做 |
